# 文件批量添加序号工具：设计文档

## 1. 目标与范围

本项目是单进程、本地运行的 Tkinter 文件重命名工具。核心目标是在真正执行 `os.rename` 前，让用户通过可编辑顺序的预览确认文件名变换。它不提供网络服务、数据库、持久化配置或撤销日志。

业务代码集中在 `main.py` 的 `FileRenameApp` 类中；应用启动后创建一个 Tk 根窗口并进入事件循环。

## 2. 架构

```text
Tkinter 控件与事件
        |
        +-- 模式与参数状态（tk.Variable）
        |       |
        |       +-- 文件发现 / 标题提取 / 规则计算
        |                       |
        |                       +-- preview_results: [(旧文件名, 新文件名)]
        |                                       |
        +------------------------------- 执行重命名 / 取消格式
                                                |
                                             os.rename
```

### 模块职责

| 部分 | 职责 |
| --- | --- |
| `FileRenameApp.create_widgets` | 创建控件、绑定事件、初始化状态。 |
| 模式切换与选择函数 | `change_mode`、`browse_folder`、`browse_file`、`refresh_folder` 负责模式和目标路径。 |
| 批量预览 | `show_batch_files` 收集非隐藏的普通文件；`generate_batch_preview` 按当前规则计算映射。 |
| 规则辅助函数 | 日期转换、序号格式识别、下一个序号计算、目标扩展名计算。 |
| 标题提取 | `extract_title_from_docx`、`extract_title_from_pdf`、`extract_title`。 |
| 文件操作 | `execute_rename` 执行预览映射；`remove_format` 去除指定格式。 |

`resource_path` 保留了打包资源路径的通用入口，但当前业务代码未调用它。

## 3. 状态模型

| 状态 | 类型/来源 | 用途 |
| --- | --- | --- |
| `current_mode` | `batch` / `single` / `title` | 决定选择器、预览与执行路径。 |
| `file_list` | 文件名列表 | 批量模式的当前顺序；拖动后按此顺序重新生成预览。 |
| `preview_results` | `(旧名, 新名)` 元组列表 | 执行重命名的唯一输入。 |
| Tk 变量 | `StringVar`、`IntVar`、`BooleanVar` | 保存预设、编号、日期、前后缀、后缀以及开关值。 |

模式切换会清空路径、两侧列表和 `preview_results`，避免将某一模式的映射用于另一模式。

## 4. 主要流程

### 4.1 批量重命名

1. 用户选择目录或刷新目录；`show_batch_files` 用 `os.listdir` 获取全部普通文件并过滤隐藏文件。
2. `generate_batch_preview` 读取规则、前后缀、扩展名和当前日期，生成每个文件的新名称。
3. 用户可拖动左侧列表，`on_drag_end` 更新 `file_list` 后再次生成预览。
4. 程序按 `preview_results` 的顺序逐项检测文件是否被占用。被占用的文件记录为“已跳过”，不会中断整批任务；未占用的文件继续按原排序调用 `os.rename`。
5. 完成后分别汇总成功、跳过和失败的文件，重新扫描目录并清空预览状态。

### 4.2 标题重命名

1. 用户选择文件并单击“提取标题”。
2. `.docx` 路径调用 `python-docx`：优先核心属性标题，再依次尝试法律类首段、标题样式、正文前段和第一段。
3. `.pdf` 路径调用 `PyPDF2`：优先元数据 `/Title`，否则取首页有效文本行中最长的一行。
4. `extract_title` 将 Windows 非法字符替换为下划线，套用预设、前后缀和扩展名，写入单条 `preview_results`。
5. 用户手动执行，或在已勾选自动重命名时立即执行。

### 4.3 特殊规则与取消格式

“忽略已符合格式的文件”只对 `序号_原文件名_日期` 规则生效：已有匹配项保持不变，新项的编号从已匹配项最大序号加一开始。匹配规则接受 1–9 位序号和四种日期格式。

“取消格式”同样只处理这个规则：它按下划线分段，移除首段序号与末段日期并保留中间部分。

## 5. 依赖与打包

- 标准库：`os`、`re`、`sys`、`datetime`、`traceback`、`platform`、`tkinter`。
- 第三方：`python-docx`（DOCX）、`PyPDF2`（PDF）。
- 可选第三方：`pywin32` 的 `win32api`/`win32con`，用于 Windows 隐藏属性；不可用时尝试 `os.stat` 回退。
- PyInstaller：两个 spec 都以 `main.py` 为入口、关闭控制台窗口；差异仅在生成的 EXE 名称。

## 6. 设计约束与风险

1. **无事务性**：批量文件按顺序重命名。重复目标或覆盖既有文件会在执行前阻止；权限不足或文件占用等运行时错误仍可能导致部分成功，且不会自动回滚。
2. **文件占用检查有限**：实现是以追加模式打开文件，无法可靠代表所有进程和所有 Windows 共享模式；批量模式判断为占用后会跳过该文件并继续处理。
3. **标题质量依赖输入**：PDF 仅从第一页文本推断，扫描件无文本；标题模式支持 `.docx` 而不支持旧式二进制 `.doc`。
4. **文件范围**：不递归处理子目录。
6. **可逆性有限**：取消格式不是通用撤销，只能还原符合指定正则的文件名，且仍可能遇到目标冲突。

## 7. 后续演进建议

若要提升可靠性，应优先增加预执行冲突检测与两阶段临时名重命名，再考虑操作日志/回滚；这些改动会改变现有行为，当前版本未实现。

## 8. 批量模式跳过占用文件

### 目标

批量重命名执行前检查每个文件是否正在使用。对确认被占用的文件不执行 `os.rename`，而是继续处理排序列表中的下一文件，直至整批处理完成。

### 预期行为

1. 以用户拖动后的 `file_list` / `preview_results` 顺序处理。
2. 对每个文件调用现有占用检测；被占用的文件加入 `skipped_files`，不再弹出“是否继续”的整批确认框。
3. 未被占用的文件沿用预览中已生成的目标名称执行重命名。
4. 结束时在结果提示中分别展示成功数、跳过数及失败数，并列出每类涉及的文件和原因。
5. 任一文件被跳过不影响后续文件的处理顺序。

### 序号规则

**已确认：保留预览结果，不重新编号。**例如排序后的预览为 `01_A`、`02_B`、`03_C`，若 `02_B` 的源文件被占用，则只执行 `01_A` 和 `03_C`。`02` 保留为空号，后续文件仍使用预览中已确认的目标名称。
